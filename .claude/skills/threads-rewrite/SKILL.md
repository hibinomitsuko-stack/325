# 焼き直し（競合のバズ投稿 → 構造そのまま・中身入れ替え）

目的は「競合と同じ骨格で、同じ強さの投稿」を作ること。借りるのは骨格（行の役割と順番）だけで、語句・論点・着地は入れ替える。
本人のエピソードや考えを足すのではなく、**競合のエピソードが置かれている場所に、本人の材料を同じ形で置く**。

## 0. 受け取るもの（足りなければ聞く）
1. 競合投稿の全文（全スレッド）と閲覧数
2. 競合のコメント欄（反論・質問・共感の中身）
3. 本人の材料：事実・商品の特徴・言われた言葉（例：酒種酵母で砂糖が少なくても満足する／しっとり保てる／でも砂糖も油もゼロではない）
4. 最後の案内（あれば）：告知・相談など。日時・条件は本人の文をそのまま使う
5. 誰のアカウントか（みつこ本人なら「7. みつこのアカウントで使うとき」も守る）

## 1. 競合を分解する（最初に必ず表にする）
- **1スレッド目は1行ずつ役割を書く**。例（米粉パン 22万閲覧）：
  1. 不調の訴え（「米粉パン食べると、なんか調子悪いんです」）← スクロールを止める核
  2. 素朴で漠然とした疑問（「米粉ってよくないんですか？」）
  3. 引用で閉じる（「と生徒さん。」）
  4. 書き手が自分の思い込みを認める（「私もね、〜そう思ってた」）
  5. 思い込みの短文反復（「小麦より米粉の方が安心。米粉はお米だから大丈夫。」）
  6. 「でも、〜しているうちに気づいた」
  7. 答えを言わずに切る
- **スクロールを止める核**を1つ特定する。焼き直しで最後まで落とさない（例：①の不調の訴え。「健康のために選んだのに」が崩れる音）
- **テーマの型**を書く（例：信じていたものへの疑い／常識の逆／やめてリスト／N選）
- 2スレッド目以降：答えの回収 → 理由・仕組み → 解決策 → 案内、のどこに何があるか

## 2. コメント欄を読んで「荒れる主張」を避ける
- 反論が付いている主張（例：「油ギトギトになるほど使ってない」）は書かない、または**先に自分から認める**（例：「砂糖も油もゼロではありません」）
- 本人がしていることと矛盾する主張は書かない（例：自分も砂糖と油を使うのに「砂糖と油が悪い」と書く）
- 特定の人・店・同業者を下げる書き方をしない

## 3. 着地を決める（真似に見えない一番の理由）
- 同じ話題に乗り、**結論をずらす**（競合「米粉を疑う」→ 焼き直し「量が見えるかどうか」）
- 着地は本人の材料に自然につながるものにする（例：手作りなら量が全部見える → 酒種酵母で頼る量が減る）

## 4. 1スレッド目を作る（ここで勝負が決まる）
1. **行の数・順番・役割は競合と同じにする**（1. の表の通り）。語句はすべて入れ替える
2. **指紋を消す**：次のどれかが残っていたら変える
   - 一字一句同じ締め（例：「と生徒さん。」）→「レッスンで、そう聞かれました。」など
   - 同じ構文の疑問文（例：「〜ってよくないんですか？」）
   - 同じ論点の言葉（例：「調子悪い」→「なにも体調が変わらない」のように向きを変える）
3. **答えを漏らさない**：1スレッド目の疑問は漠然とさせる。2スレッド目で出す論点の言葉（例：「砂糖と油」）を1スレッド目に入れない
   - 疑問の矢印を「対象」から「自分」に向けると、漏れずに自分ごとになる（例：「米粉ってよくないんですか？」→「私の選び方、間違ってるんでしょうか？」）
4. **「私もそう思っていました」型の1行は必ず残す**（書き手が思い込みを認める＝読む人の警戒が解ける。削ると上から教える投稿になる）
5. 短文の反復は2つまで（例：「米粉なら安心。お米だから大丈夫。」を1行に）
6. 常識が崩れるのは最初の2〜3行で完結させる（スマホで最初に見えるのは2〜3行）
7. 「問題は、〇〇じゃなくて、」のように答えの手前で切る
8. 長さの目安は7行前後。短くしすぎて「誰の話か」「なぜこの人が知っているか」が消えないようにする

## 5. 冒頭案を3〜5案出して採点する
各案に★（5段階、0.5刻み可）と一言の理由。採点の観点：
| 観点 | 見ること |
|---|---|
| 骨格 | 競合の行の役割・順番を守っているか。スクロールを止める核が残っているか |
| 指紋 | 競合と同じ語句・構文・締めが残っていないか |
| 漏れ | 2スレッド目の答えを先に言っていないか |
| 自分ごと | 読む人が「私のことだ」と思えるか |
| 接続 | 2スレッド目の1行目に自然につながるか |
- 競合と同じ入り方の案は「避ける例」として1つ示してよい（★3以下）
- 推す案を1つ選び、理由を書く

## 6. 全文を書く
- **2スレッド目**：1スレッド目の切れ目をそのまま受けて答えを出す（例：「その中に、どれだけ砂糖と油が入っているかでした。」）→ 理由・仕組み → 都合の悪い事実を自分から認める → 本人だけが言える着地
- **3スレッド目**：本人の材料で解決策（例：酒種酵母）→ もう一度、ゼロではないことを認める → 案内（本人の文をそのまま）→ 誘いの一文
- 競合のスレッド数に合わせる（3なら3、4なら4）

## 7. みつこのアカウントで使うとき（@mitsukoihle）
- `threads/knowledge/07_ng-rules.md` と `11_tone_rules.md` を守る：「あなた」「LINE」「ストアカ」「単発グループ講座」「金額」「スレッズ」「かもしれません」・ハッシュタグ・URLは書かない。1スレッドは500文字以内
- 事実は `01_profile.md`・`04_positioning.md`・`10_students.md`・`post-history.md` にあるものだけ。ない事実は作らず「要確認」に挙げる
- 案内は `08_strategy.md` のとおり（朝の①だけ「30分の無料個別相談は、プロフィールのリンクから」）
- キューに入れるときは `threads-writer` の形式（`approved: false`）。`source`（競合URL・閲覧数）と `structure`（借りた骨格）を必ず書き、`threads/ops/codex-sources.md` に記録する

## 8. 仕上げの点検（出す前に必ず）
1. 競合と同じ文字が10文字以上続く箇所がない（並べて確認。引用符の中も含む）
2. 1スレッド目に、2スレッド目の答えの言葉が出ていない
3. コメント欄で反論された主張を書いていない／先に認めている
4. 本人の材料と矛盾していない
5. 「生徒さんに聞かれた」などの引用は、本人が実際に聞いた言葉か確認する（分からなければ「要確認」）

## 9. 出力の形
1. 競合のバズ構造（1スレッド目の行ごとの役割・核・テーマの型）
2. コメント欄から分かったこと（避ける主張）
3. 冒頭案3〜5案（★と理由・推す案）
4. 全文（【1/3】【2/3】…）
5. 対応表（競合 → この投稿）
6. 真似に見えない仕掛け（3つまで）
7. 確認してほしいこと（実際の言葉か・事実か）
